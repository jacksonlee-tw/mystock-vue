## 詳細備註

### 1. TPEX（上櫃股）OHLCV 爬蟲 — 未開始

- 端點：`https://www.tpex.org.tw/web/stock/aftertrading/daily_trading_info/st43_result.php`
- 目前 `services/fetcher.py` 只處理 TWSE（上市）股票，`config.py` 的 `DEFAULT_STOCKS` 也全是上市股。
- 需求：新增 `d`（民國年月）、`stk_no` 參數解析，格式與 TWSE JSON 略有不同，需另外處理逗號千分位與民國年轉換。
- 建議實作位置：可比照 `markets/tw.py` / `markets/us.py` 的 `MarketAdapter` 走法，或至少先在 `services/fetcher.py` 補一個 `fetch_daily_quotes_otc()`。

### 2. MOPS 季財報 / EPS 爬蟲 — 初版完成，待驗證

- 新增 `services/mops_eps_fetcher.py`，比照既有 `services/mops_fetcher.py`（月營收）的容錯慣例：TYPEK 依序嘗試 `sii`/`otc`/`rotc`、查無資料一律回傳 `None`、節流 3 秒。
- **已知限制**：`mops.twse.com.tw` 對外部/雲端網段 IP 有嚴格 WAF（月營收爬蟲的既有註解已提過），本開發環境無法對 `ajax_t163sb04` 發出真實請求驗證回傳表格結構。目前的欄位定位規則（`_EPS_ROW_RULES`／`_first_amount_value`）是依 MOPS 綜合損益表慣用格式（會計項目＋本期金額＋本期%＋去年同期金額＋去年同期%）推導，**尚未用真實回應驗證過**。
- **上線前待辦**：建議在台灣網段（或有台灣 IP 的機器）手動呼叫一次 `fetch_quarterly_eps_single()`，確認：
  1. 回傳的表格是否真的能被 `pandas.read_html(flavor="lxml")` 解析出來（金融業/一般業/證券業的 XBRL 表格結構不同，可能要多分支處理）。
  2. `"基本每股盈餘"` 這個關鍵字是否精準命中目標列，有無多列同時命中的狀況。
  3. `_first_amount_value` 抓到的欄位是否真的是「本期」金額而非「去年同期」。
- 新增 API：`POST /api/v1/fundamentals/eps/trigger`、`GET /api/v1/fundamentals/eps/status`、`GET /api/v1/fundamentals/eps/{stock_id}`（見 `api/v1/endpoints/fundamentals.py`）。
- 資料落地：`data/tw/{stock_id}_eps.json`，key 為 `YYYY-QN`。

### 5. 爬蟲容器化 — 完成

- 新增 `backend/Dockerfile`：基於 `python:3.11-slim`，安裝 `requirements.txt`，以 `uvicorn main:app` 啟動（排程器已內嵌在 FastAPI lifespan 裡，見 `services/scheduler.py`，不需要另開 `crawler_worker` 容器）。
- `docker-compose.yml` 新增 `app` 服務：`depends_on` 等 `db` healthy、`flyway` migrate 完成才啟動；掛載 `./data` 與 `.env` 為 volume 以保留爬蟲落地的 JSON 與透過 UI 修改的追蹤股票清單。
- 與文件七節的差異：文件建議獨立 `crawler_worker` 容器＋`schedule` 套件持續監聽；實際做法是排程器與 API 服務同一個容器／同一個 event loop（`AsyncIOScheduler`），少一個容器、部署更簡單，但代價是排程與 API 服務生命週期綁在一起（重啟 API 也會重啟排程）。如果未來排程工作量變重、需要獨立擴縮，才需要真的拆成文件建議的 `crawler_worker`。
