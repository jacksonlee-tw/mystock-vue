## 詳細備註

### 7. 持股部位追蹤（最小可行版）— 下一步

使用者已在討論中選定「持股部位追蹤（最小可行版）」為下一步方向：只做風控策略需要的最小資料模型
（`positions` 表：`symbol`、`entry_date`、`entry_price`、`qty`），**不**做 [docs/8.個人投資記帳功能](../8.個人投資記帳功能/個人投資記帳功能_design.md)
完整的交易紀錄／已實現損益／現金流模組。

解鎖項目（賣股策略.md 第三節「風控與紀律策略」）：

- **雙重絕對停損**：價格停損（T+1/T+2 收盤價 < 進場當日最低價）+ 時間停損（3 個交易日內未反彈強制平倉）
- **固定停損與固定停利**：例如 -5% / +15%
- **移動停利**：自持倉期間最高價回落 N%（例如 10%）強制出場

實作要點（先記下來，動工時再展開）：

- 需要新增 `positions` 資料表（或先用 JSON 落地，比照現有 `data/_alerts/` 的模式）
- 這三個策略跟現有的「掃描全市場找訊號」模式不同，是「針對已持有部位逐日檢查出場條件」，
  Scanner 的資料流向可能需要新的進入點（不是走 `get_target_stocks()` 全市場掃描，而是走「使用者的持倉清單」）
- 新增 `strategies/conditions_risk.py`，条件簽章沿用 `(ctx, idx, params) -> List[dict]` 慣例，
  但 `ctx` 需要額外帶入該筆持倉的 `entry_date`/`entry_price`（現有 `ScanContext` 沒有這兩個欄位，需擴充或另建 `PositionContext`）
- 需要一個最簡單的「新增/查詢持倉」API，供前端與策略引擎共用

### 8. Universe 選股池 + TPEX 上櫃資料源 — 未開始

同時卡住 #9、#10、#11 三項，是籌碼選股.md 剩餘工作量最大的一塊（文件自估 Phase 1 + Phase 2 共約 22 小時）。

- `markets/tpex.py`（新）：上櫃行情／法人／信用三個 TPEX OpenAPI 端點的 Adapter，欄位需正規化
  （文件註明 TPEX JSON key 有空白與拼字不一致，例如 `LatesAskPrice`、`Dealers-TotalSell` vs `Dealers -TotalSell`）
- 市值計算：上市用「實收資本額 ÷ 面額 × 收盤價」（面額為字串需正則解析），上櫃直接取 `tpex_daily_market_value` 現成排名
- `universe_snapshots` 資料表 + point-in-time 快照（防回測倖存者偏差，見文件 §4.3）
- 排除規則：ETF/ETN/特別股/處置股/注意股/流動性/新上市櫃（見文件 §4.1）
- **注意**：文件裡列的端點回應格式（TPEX 欄位、TWSE 開放資料集）是文件作者在 2026-08-12 實測記錄的，
  跟先前 MOPS 月營收/EPS 爬蟲遇到的狀況類似——本機開發環境不一定能直接驗證真實回應，
  正式開工前建議先用小範圍請求确認欄位是否與文件記載一致，不要照單全收就寫死解析邏輯。
