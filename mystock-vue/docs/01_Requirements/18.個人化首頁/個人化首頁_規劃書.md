## 1. 目的與範圍

### 1.1 需求來源

系統已累積 30+ 個頁面、6 大選單分類，卻沒有一個「打開系統後先看哪裡」的入口。使用者要的是：**一個方便查找想找的股票的個人化首頁，以既有功能為 base**（分析後的股票資訊、推薦購買等），並且**每個區塊都能自己勾選要不要顯示**（2026-09-22 追加）。

### 1.2 交付範圍

| 項目 | 內容 |
|---|---|
| 路由 | `/` 改為個人化首頁 `HomeView`；原熱力圖搬到 `/heatmap`（路由 name `heatmap-dashboard` 不變） |
| 四大區塊 | 快速查找／今日盤勢／訊號與推薦／我的部位，共 13 個 widget |
| Widget 自選 | 首頁右上「自訂版面」面板，勾選即時生效，設定存 `localStorage` |
| 最近瀏覽 | 新增 `useRecentStocks`（`localStorage`），個股頁載入成功後記錄 |
| 搜尋交棒 | 首頁大搜尋框把輸入字串交給既有 `Omnibox` 處理（ADR-04） |
| 登入降級 | 首頁不要求登入；未登入時個人化 widget 不發請求、改顯示登入提示 |
| 連結修正 | 所有原本指向熱力圖的硬寫 `/` 連結改指 `/heatmap` |
| 雛形 | `prototype/index.html`（單檔、假資料） |

### 1.3 不在本文件範圍

| 不做 | 原因 |
|---|---|
| widget 拖曳排序 | 使用者要的是「勾選要顯示的功能」；順序固定依區塊排列即可，避免引入拖曳套件與版面持久化的複雜度 |
| 跨裝置同步偏好 | 後端無使用者表、無通用偏好儲存（見 §2.1），需另開後端 singleton 欄位或端點；與「零後端改動」決策衝突 |
| 後端彙總端點（如 `GET /home/overview`） | 見 ADR-02 |
| 清理其餘 Sakai 樣板殘骸（`Dashboard.vue`、`views/pages/*`、`views/uikit/*`） | 與首頁無關，不在本次範圍；僅刪除 `HomeDashboard.vue`（本功能的未完成前身） |
| 修改熱力圖本身的功能 | `/heatmap` 功能與搬遷前完全一致，僅換路徑 |

### 1.4 名詞定義

| 名詞 | 本文件定義 |
|---|---|
| **widget** | 首頁上可被使用者勾選顯示／隱藏的一張卡片或一個元件，在 `useHomeWidgets` registry 中以 `id` 識別 |
| **區塊（section）** | widget 的分組：`quick`（快速查找）／`market`（今日盤勢）／`signals`（訊號與推薦）／`positions`（我的部位） |
| **owner 登入** | 系統為單一擁有者模式，以 cookie session 認證；`GET /api/v1/auth/session` 回 200 即為已登入 |

## 2. 現況盤點

### 2.1 缺口與殘骸

| # | 現況 | 影響 |
|---|---|---|
| **G1** | `/` 目前渲染 `views/HeatmapDashboard.vue`（全市場動態熱力圖） | 它是功能很深的單一工具頁（週期切換、概念標籤分群、卡片／Treemap 切換），不是導航頁；使用者打開系統直接掉進熱力圖 |
| **G2** | `views/HomeDashboard.vue` 存在但**從未掛上任何路由、無任何 import** | 內容是 Sakai 樣板殘骸（硬寫「歡迎，王小明」、問卷公告、`support@example.com`），是一次沒做完的首頁嘗試；留著會造成「哪個才是首頁」的混淆 |
| **G3** | 全專案沒有「最近瀏覽」機制 | `localStorage` 僅有 5 個 key（市場、外觀、副圖指標、MarketScreener 欄位等） |
| **G4** | 後端無使用者表、無通用偏好儲存 | `activity_log` 註解明載「本系統為單一擁有者，無使用者表」，故首頁偏好與最近瀏覽只能放 `localStorage` |
| **G5** | `service/alertApi.js` 的 `getAlerts()` 漏傳 `category` 參數 | 後端 `GET /alerts` 早已支援 `category`（`technical/chip/fundamental/stock_picking/risk/...`），前端沒帶，首頁無法只取選股或風控類警示 |

### 2.2 可直接重用的既有資產（零重寫）

| 資產 | 用途 |
|---|---|
| `components/Omnibox.vue` | 跨市場模糊搜尋（`GET /markets/suggest`）、市場篩選、鍵盤導航、Ctrl+K；首頁搜尋框驅動它，不另寫第二套 |
| `components/MacroDashboardBanner.vue` | 總經燈號條（大盤 20MA/60MA 位階、US10Y、DXY + sparkline），自己管 loading／error |
| `components/AlertTimeline.vue` | props `{ alerts, strategyList, showChartLink, compact }`，`compact` 為窄欄變體 |
| `components/WatchlistStarButton.vue` | 加入追蹤星號，背後走 `useTrackingList` 快取，不會每顆星打一次 API |
| `composables/useMarket.js` | 單例 `currentMarket`／`marketMeta`；首頁必讀它，**不可寫死 `'tw'`** |
| `composables/useTrackingList.js` | 追蹤清單單例快取，內建 401 記憶（`deniedMarkets`），未登入不重複打 |
| `utils/marketColors.js`／`utils/format.js` | 漲跌色（紅漲綠跌，tw/us 皆同）與數字格式 |
| `service/ownerApi.js` | `whoami()`＋登入／登出時派送全域 `owner-auth-changed` 事件 |

### 2.3 既有 API 的重要語意

- `GET /api/v1/stocks/heatmap` **只回傳 `is_crawl_enabled` 的追蹤標的**（`get_heatmap_data()` 以 `tracking_service.get_crawl_enabled_symbols()` 過濾），並非全市場。故首頁那張卡的正確語意是「**我的追蹤清單今日表現**」，比全市場排行更貼近個人化。
- `GET /api/v1/watchlist` 已由後端算好 `gap_pct`／`is_near_target`／`is_reached`；`gap_pct = 股價 / 目標價 - 1`（`target_price` 為空時為 `null`）。
- `GET /api/v1/ai/war-room` 已是「監控清單 × 當日最新報告」的單次彙總（避免 N+1），每列含 `verdict`（`bullish`／`bearish`／`neutral`）與 `is_price_hit`（收盤已觸及目標價或停損）。
- 所有 `portfolio`／`watchlist`／`ai` 端點掛 `require_owner`，須使用 `privateApiClient`（`withCredentials`）；未登入回 401。

### 3.4 Widget 自選機制

**`composables/useHomeWidgets.js`** 匯出 `{ registry, isEnabled(id), toggle(id), enabledIn(section), resetAll() }`。

**`components/home/HomeWidgetSettings.vue`**：首頁右上「自訂版面」按鈕開啟的 `Popover`，依區塊分組列出 Checkbox，附「全部重設」。未登入時 `requiresOwner` 的項目顯示為停用並標註「需登入」。

**儲存格式：存「停用清單」，不存「啟用清單」（ADR-03）**

```jsonc
// localStorage["mystock.homeWidgets"]
["war-room", "risk-alerts"]     // 使用者取消勾選的 widget id
```

| 行為 | 說明 |
|---|---|
| 預設 | key 不存在或內容非法 → 視為空陣列 → 全部顯示 |
| 新增 widget | 不在舊使用者的停用清單裡 → 自動出現（若存啟用清單，新 widget 會因不在舊清單而被隱藏） |
| 下架 widget | 停用清單裡殘留的未知 id 直接忽略，不報錯 |
| 區塊全空 | 某區塊 widget 全部取消勾選時，**連區塊標題一併隱藏**（`enabledIn(section).length === 0`） |
| 讀寫失敗 | 每次 `getItem`／`setItem`／`JSON.parse` 皆包 `try/catch`（無痕視窗、封鎖 site data 會丟例外），失敗時退回預設值，本次 session 內以記憶體狀態運作，不炸畫面 |

**關鍵：資料抓取必須跟著勾選狀態走。** 被停用的 widget 不發請求（含被共用的請求：例如 #3 與 #11 共用 `holdings`，兩者皆停用才不發）。這同時是首屏請求數的實際控制點。

### 3.5 快速查找與最近瀏覽

- **搜尋交棒**：新增 `composables/useOmnibox.js`（單例 `state = { visible, initialQuery }` ＋ `openOmnibox(initialQuery)`，比照 `useWatchlistQuickAdd.js` 模式）。`Omnibox.vue` 的 `visible` 改綁 `state.visible`，開啟時從 `state.initialQuery` 帶入並立即搜尋；保留 Ctrl+K 與 `defineExpose({ open })`（`AppTopbar` 不用改）。首頁大搜尋框是真的 `<input>`，第一個按鍵就 `openOmnibox(輸入字串)`。

### 3.6 登入降級

## 4. 兩條硬性規則的落實方式

> 出處：`CLAUDE.md`「Hard rules」，使用者標明為常設要求、不得退化。

### 4.1 規則 #1：切換控制項不可整頁 refresh 跳回頂端

首頁上會觸發重抓的是頂列 tw/us 切換。

- `HomeSectionCard` 的 refresh 一律**保留前一次內容掛載中**，只加半透明遮罩＋spinner；
- 只有「第一次載入且完全沒資料」才渲染整張 skeleton，判斷式比照 `StockDashboard.vue` 的 `v-if="loading && !chartData"` / `v-else-if="chartData"` ＋ inline refresh overlay；
- **禁止**用單一 `loading` ref 把整個內容區換成小轉圈——那會讓頁面高度塌陷、瀏覽器把捲軸彈回頂端且不會還原；
- 各卡獨立錯誤隔離：某張卡失敗只顯示該卡的錯誤態，不影響其他卡。

### 4.2 規則 #2：同列 KPI／指標卡高度必須一致

- 適用範圍：#5 大盤指數卡（3 張）、#10 KPI 卡（4 張）皆為 CSS Grid `v-for`。
- 陷阱：`assets/layout/_utils.scss` 的 `.card { margin-bottom: 2rem; &:last-child { margin-bottom: 0 } }`——迴圈最後一張少一個 bottom margin，grid 拉齊列高後比別人高。
- 作法：**每一張 grid 卡片都加 `!m-0`**，間距交給 grid 的 `gap-*`；比照 `StockDashboard.vue` 的 KPI grid。
- 雛形以 `align-items: stretch` 呈現此要求。

## 7. 決策紀錄（ADR）

| ID | 決策 | 替代方案與否決理由 |
|---|---|---|
| **ADR-01** | **取代 `/`**，熱力圖搬到 `/heatmap`；而非新增 `/home` | 使用者於規劃階段裁決。新增 `/home` 會讓 logo、`ErrorState`「返回首頁」、瀏覽器根網址仍落在熱力圖，「首頁」名不副實，且需另外教育使用者；取代 `/` 的代價僅是修改 6 處硬寫連結（§3.1）。連帶決策：首頁**不掛 `requiresOwner`**，以降級取代強制登入（§3.6） |
| **ADR-02** | **純前端併發呼叫既有 API，不新增後端彙總端點** | 替代方案 `GET /api/v1/home/overview` 一次回傳全部：可減少請求數，但需跨 alerts／portfolio／ai／macro／indices 五個領域寫聚合層、在後端處理「未登入時哪些欄位省略」，且勾選停用的 widget 仍會被算出來（違反「被關掉不發請求」）。現有端點皆已針對彙總設計（`indices/overview`、`ai/war-room` 註解即寫明用途），前端併發 8–13 個請求且各卡錯誤隔離，成本可接受；若日後實測偏慢再回頭評估 |
| **ADR-03** | Widget 勾選狀態存**停用清單**而非啟用清單 | 存啟用清單時，日後新增 widget 不在舊使用者的清單內，會被預設隱藏、使用者永遠不知道有新功能；存停用清單則新 widget 自動出現，使用者不想要再取消勾選即可。副作用：未知 id 需忽略（AC-13） |
| **ADR-04** | 首頁搜尋**交棒給 `Omnibox`**，不重寫搜尋 | 替代方案是在首頁內嵌一套搜尋結果下拉：會產生第二套模糊搜尋、鍵盤導航與市場篩選邏輯，日後兩套行為必然漂移。以 `useOmnibox` 單例把輸入字串交給既有元件，改動集中在 `Omnibox.vue` 小範圍（`visible` 綁單例、開啟時帶入初始查詢），Ctrl+K 與 topbar 入口不受影響 |
