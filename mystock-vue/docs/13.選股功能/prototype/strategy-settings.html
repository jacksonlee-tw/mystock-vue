調整門檻只改 YAML、不改程式、不需重啟服務（config_loader 每次呼叫重新解析） §7 / AC-9

單位陷阱：dividend_yield_min 是百分比數值（4.0 = 4%）。 v1.0 規格寫成 0.05 等於門檻 0.05%，形同沒有門檻（§2.2-5）。 同理 stop_loss_pct 在既有 YAML 是 8.0 而非 -0.08。

不支援的欄位（寫了會被靜默丟棄）
§2.2-2 / §7
config_loader.StrategyDef 只解析 id / name / category / enabled / markets / conditions / filters / cooldown_days / scope / max_picks_per_day / sort_by / universe_tier。 以下欄位不會報錯、也不會生效 —— 最容易誤以為「已設好風控」的坑。
risk_level: "NORMAL"丟棄
capital_weight: 0.5丟棄
universe: "large_cap_tw"丟棄（應用 universe_tier）
timeframe: "1D"丟棄
risk_management: { ... }丟棄（出場走獨立 risk 策略）
更嚴重：conditions 若寫成 dict（如 fundamental: / technical: / chips: 三個 key）， scanner.py 迭代出的是字串 key，condition_cfg.get("type") 會拋 AttributeError 且不在 try 內 —— 整個 scan_market() 會中斷，當日所有策略都不出訊號（§2.3-1、AC-10）。
