## 1. 目的與範圍

### 1.1 目的

在**常態市況**下（非系統性崩盤），從全市場找出「**下檔風險有限、且已出現止跌跡象**」的標的，輸出為每日選股名單，走既有警示管線推播。核心要求三條：

1. **不猜最低點**：訊號必須包含「右側止跌確認」，避免在下跌中繼站發出買進訊號。
2. **不接價值陷阱**：低估值必須搭配「營收未連續衰退」的基本面守衛。
3. **完全長在既有引擎上**：條件一律是 `@condition` 註冊的函式、門檻一律落在 `strategy_config/strategies.yaml`，不新建第二套掃描器、不新建第二個設定檔（《策略架構》§6、《選股爬蟲》ADR-SP-01）。

### 1.2 範圍

| 範圍內 | 範圍外（本文件不涵蓋） |
|---|---|
| 「相對低點」選股策略的**需求定義**與門檻表（§4） | 程式開發、YAML 實際套用（本文件只給規格範本） |
| 需新增／可沿用的條件函式**規格**（§5） | 回測與參數最佳化（專案無回測模組，見《選股爬蟲》§1.2） |
| 估值歷史深度的資料前置需求（§6） | 全市場資料表與爬蟲設計（屬《選股爬蟲》§3） |
| 名單語意、冷卻、排序需求（§9） | 選股池（universe）分層建置（屬《籌碼選股》） |
| 出場與風控需求，以及現行架構限制（§8） | 自動下單、資金配置與分批加碼的**執行**（見 §8.3） |
| 驗收準則與開放問題（§11、§13） | 美股（無等價估值／法人／信用交易來源，見 §2.2-10） |

### 1.3 名詞

| 名詞 | 本文件的定義 |
|---|---|
| 相對低點 | **相對於該股自身的估值歷史與均線位置**而言的低檔；不是「全市場最便宜」，也不是「歷史最低價」 |
| 狀態式條件 | 判斷「當日是否處於某狀態」（例：今天 BIAS60 ≤ −15%）。**與既有 `bias` 條件的跨越式語意不同**，見 §2.2-4 |
| 跨越式條件 | 只在「昨天不成立、今天成立」的那一天觸發（既有 `bias`／`alignment`／`price_cross` 皆屬此類） |
| 右側確認 | 價格已出現反轉跡象後才進場（帶量收復均線）；相對於「左側」＝下跌途中預先承接 |
| 價值陷阱 | 估值低是因為獲利即將下修，而非市場錯殺 |
| Point-in-time | 評估第 `idx` 根 K 棒時只能看見該日已公開的資料（月營收次月 11 日起可見，`indicators/fundamental.py`） |

### 1.4 與《極端抄底》《選股爬蟲》的分界（避免重複開發）

三份文件都談「低檔買進」，但觸發前提與風險等級完全不同，**必須分清楚，否則會做出第二套抄底模組**：

| 面向 | 本文件（相對低點） | 《極端抄底》`crisis_rebound` | 《選股爬蟲》`stock_pick_resonance` |
|---|---|---|---|
| 前提 | 常態市況，每日可掃 | **大盤環境鎖**：指數單日跌 ≥3% 或指數 BIAS20 ≤ −8% 才喚醒 | 常態市況 |
| 選股語意 | 便宜 ＋ 超跌 ＋ 洗盤 ＋ **止跌確認** | 恐慌錯殺、跌停打開、接刀 | **成長股**：估值合理 ＋ 營收高成長 ＋ 法人買超 |
| 估值取向 | 低 PE／低 PB／高殖利率（價值型） | 不看估值，看跌停與極端乖離 | `pe_max: 20` ＋ `revenue_yoy_min: 15`（成長型） |
| 技術取向 | BIAS60 ≤ −15%、KD 超賣後回升 | BIAS20 ≤ −25%、BIAS60 ≤ −30% | 收盤站上 MA20（順勢） |
| 風險等級 | NORMAL | **CRITICAL**（護欄須 hardcode、資金隔離） | NORMAL |
| 實作狀態 | 本文件提出，**尚未實作** | 文件 v2.0 Draft，**程式碼零實作**（全庫查無 crisis 相關實作） | **已實作**（`conditions_pick.py`、YAML `pick_multi_factor_resonance`） |

> **結論**：本策略是《選股爬蟲》選股家族的**第四個成員（價值反轉型）**，與既有三個選股策略平行，**不是**《極端抄底》的簡化版。《極端抄底》的大盤環境鎖、白名單、雙重停損等 CRITICAL 護欄**不納入本文件**；本策略也不得被當成崩盤抄底工具使用（見 §13 Q-4）。

### 2.2 與現行程式碼／資料的落差（可落地性）

| # | v1.0 隱含的假設 | 判定 | 現況與修正 |
|---|---|---|---|
| 1 | 同一策略下並列 fundamental／technical／chips 三組條件，語意為 **AND** | ❌ | `scanner.py:212` 是 `for condition_cfg in strategy.conditions:`，同一策略的多個條件**各自獨立觸發（OR）**。照 v1.0 寫，只要殖利率達標就會出訊號，技術面與籌碼面形同虛設。修正：AND 必須寫在**單一複合條件函式**內（《選股爬蟲》ADR-SP-06，`stock_pick_resonance` 即為範例） |
| 2 | 策略節點支援 `risk_level`／`capital_weight`／`universe`／`timeframe`／`risk_management` | ❌ | `config_loader.StrategyDef`（`config_loader.py:19`）只有 `id`／`name`／`category`／`enabled`／`markets`／`conditions`／`filters`／`cooldown_days`／`scope`／`max_picks_per_day`／`sort_by`／`universe_tier`。其餘欄位會被**靜默丟棄**（不報錯、不生效），是最容易誤以為「已設好風控」的坑。修正見 §7 |
| 3 | 條件以 `indicator` / `operator` / `value` 三元組表達（通用運算式直譯器） | ❌ | 專案**沒有**運算式直譯器。條件是 `type` ＋ **平鋪參數**，比較語意寫死在條件函式內（例：`pe_max`／`pb_max`／`dividend_yield_min`）。要比較新指標就得新增條件函式，不能靠 YAML 造新運算式 |
| 4 | `bias_ma60 <= -15` 是「處於超跌狀態」的篩選 | ❌ | 既有 `bias` 條件（`conditions_tech.py:166`）是**跨越式**：`curr <= oversold and prev > oversold`，只在跌破門檻的**那一天**觸發。選股需要的是「今天仍在超跌區／近期曾進入超跌區」，語意不同 → 需新增狀態式判斷（§5.2） |
| 5 | 殖利率門檻寫 `0.05` 代表 5% | ❌ | **單位錯誤**：`daily_valuation.dividend_yield` 是百分比數值（`NUMERIC(8,2)`，5% 存為 `5.00`），既有 YAML 也寫 `dividend_yield_min: 4.0`。寫 `0.05` 等於門檻 0.05%，**形同沒有門檻**（同理 `stop_loss_pct: -0.06` 與既有 `stop_loss_pct: 8.0` 的單位也不一致） |
| 6 | 估值（PE／PB／殖利率）隨時可用 | ⚠️ | 只在 `DATA_SOURCE=postgres` 且全市場估值已落地時才有（《選股爬蟲》ADR-SP-04）。JSON 模式下 `requires=("valuation",)` 會讓條件在 `scanner.py:216` 被**靜默跳過** —— 不報錯、也不出訊號。需求上必須明列此降級行為（§11 AC-7） |
| 7 | 營收條件寫 `revenue_yoy_2m >= 0` | ⚠️ | 語意可用既有 `revenue_growth`（`yoy_min` ＋ `consecutive_months`）表達，但**必須走 point-in-time 可見性**：月營收於**次月 11 日**起才可見（`indicators/fundamental.py:6`），直接讀當月數字會造成 look-ahead bias（《選股爬蟲》ADR-SP-03） |
| 8 | 選股結果會涵蓋所有標的（含 ETF） | ⚠️ | `scanner.py:207`：`category` 為 `chip` 或 `stock_picking` 的策略會自動排除 ETF／ETN／TDR／特別股／受益證券。本策略掛 `stock_picking` 即自動享有此保護，**但也代表 `0050`／`006208` 等永遠不會被本策略選出** —— 這是預期行為，需寫進需求避免日後被當成 bug（§11 AC-6） |
| 9 | 停損／停利可綁在選股策略上 | ❌ | 出場走**獨立入口** `scan_positions()`（`scanner.py:310`），且它取 `category ∈ {risk, fundamental}` 的**所有**策略，對**所有持股**一律套用。現行架構**無法**「只對本策略買進的部位設 −6% 停損」。此為架構限制，需求上須接受或另立需求（§8.3） |
| 10 | 適用市場未指明 | ⚠️ | 估值（BWIBBU）、三大法人（T86）、信用交易（MI_MARGN）、月營收（MOPS）**皆為台股專屬**，`conditions_chip.py:31` 也硬性 `if ctx.market != "tw": return []`。本策略 `markets: ["tw"]`，美股列範圍外 |

### 2.3 v1.0 附錄程式片段的具體問題

| # | 問題 | 說明 |
|---|---|---|
| 1 | **會讓每日掃描崩潰** | v1.0 的 `conditions:` 是 dict（`fundamental`／`technical`／`chips` 三個 key），但 `scanner.py:212` 對它做 `for condition_cfg in strategy.conditions:` → 迭代出的是**字串 key**，下一行 `condition_cfg.get("type")` 會拋 `AttributeError`。該行**不在** try 區塊內（try 只包住 `spec.func(...)`），整個 `scan_market()` 會中斷，當日**所有**策略都不會出訊號 |
| 2 | 條件型別皆未註冊 | `pe_ratio`／`pb_ratio`／`dividend_yield`／`bias_ma60`／`rsi_14`／`rebound_trigger`／`margin_balance_change_pct`／`institutional_net_buy` **沒有一個**存在於 `CONDITION_REGISTRY`。即使結構改成 list，也會全部在 `scanner.py:213` 被略過（`if not spec: continue`），策略等同關閉 |
| 3 | `risk_management` 區塊無效 | 見 2.2-2，`StrategyDef` 不解析此欄位，四項風控（`stop_loss_pct`／`time_stop_days`／`trailing_stop_pct`／`take_profit_bias_ma60`）**全部不會生效**。其中 `take_profit_bias_ma60`（季線正乖離停利）現行**沒有對應條件函式**，須另立需求 |
| 4 | 兩段 Python 腳本重複且輸出路徑錯誤 | 同一份設定被寫兩次（先 `yaml.dump` 再貼一份等效內容），且都輸出到 `bottom_fishing_strategy.yaml`。本專案**只讀單一設定檔** `backend/strategy_config/strategies.yaml`（`config.get_strategy_config_path()`），不支援多檔或 `config/strategies/` 目錄（該路徑亦會與既有 `backend/config.py` 撞名，見 YAML 檔頭註解） |
| 5 | 產檔腳本不屬於需求文件 | 需求規格書應描述「要什麼」與「如何驗收」；`yaml.dump` 的產檔程式碼既非需求也非設計，且與實際 schema 不符，留著只會誤導。**v2.0 已刪除**，改以 §7 的 YAML 範本（符合現行 schema）取代 |

## 4. 策略需求定義：`pick_relative_low_zone`

### 4.1 策略屬性

| 屬性 | 值 | 說明 |
|---|---|---|
| `id` | `pick_relative_low_zone` | |
| `name` | 相對低點承接精選 | |
| `category` | `stock_picking` | 自動享有 ETF 排除（§2.2-8），並可被推播依 category 路由 |
| `scope` | `universe` | 全市場掃描；universe 未建置前依 ADR-SP-02 降級為 `all_tracked` |
| `markets` | `["tw"]` | 美股無等價資料來源 |
| `direction` | `pick_relative_low` | `pick_` 前綴在 `direction.py` 已歸類為 `bullish`／`BUY`，**無須改 `direction.py`**；前端 `utils/alertDirection.js` 需登記文案 |
| 風險定位 | NORMAL（非 CRITICAL） | 與《極端抄底》的分界見 §1.4 |

### 4.2 P0 條件組成（**全部 AND**，寫在單一複合條件 `relative_low_zone` 內）

| # | 條件 | 門檻（YAML 可調） | 資料來源 | 目的 |
|---|---|---|---|---|
| C1 | 估值低檔 | `pe_max: 15`、`pe_min: 0.1`、`pb_max: 1.5`、`dividend_yield_min: 4.0` | `ctx.valuation`（當日） | 安全邊際；`pe_min` 排除 PE 異常小的髒資料 |
| C2 | 基本面守衛 | `revenue_yoy_min: 0`、`revenue_consecutive_months: 2` | `ctx.revenue_yoy` ＋ `ctx.revenue`（point-in-time） | **避開價值陷阱**：近 2 個已公開月份 YoY 皆不為負 |
| C3 | 超跌狀態 | `bias_ma_period: 60`、`bias_max: -15`、`bias_lookback_days: 10` | `ctx.bias[60]` | 近 10 日內**曾**出現 BIAS60 ≤ −15%（允許已反彈數日才確認，非只看當天） |
| C4 | 動能超賣 | `kd_params: [9,3,3]`、`kd_oversold: 20`、`kd_lookback_days: 10` | `ctx.kd[(9,3,3)]` | 近 10 日內 K 值曾 ≤ 20（**取代 v1.0 的 RSI**） |
| C5 | 籌碼洗盤 | `margin_change_window: 10`、`margin_change_max_pct: -5`、`institutional_window: 5`、`institutional_min_buy_days: 3` | `chip.change_pct()`／`chip.net_buy_days()` | 融資近 10 日減幅 ≥5%（浮額清洗）＋ 外資**或**投信近 5 日至少 3 日淨買超 |
| C6 | **右側止跌確認** | `above_ma_period: 20`、`volume_multiple: 1.5` | `ctx.ma[20]`／`ctx.volumes`／`ctx.volume_ma` | 收盤 ≥ MA20 **且** 當日量 ≥ 5 日均量 × 1.5。**必要條件，不得降級為濾網**（ADR-RL-03） |

**缺值處理**：任一條件所需數值為 `None` 一律視為**不成立**，不補值、不沿用前一日（《選股爬蟲》ADR-SP-08）。

**C5 視窗改 10 日的理由**：既有 `chip_bottom_turnover` 用 20 日視窗判斷「長期融資退場」；本策略已用 C3 確保處於超跌段，融資在超跌段本就減得急，10 日視窗更貼近「近期正在洗盤」而非「一個月前洗過」。門檻同為 −5%，語意刻意與既有籌碼策略保持一致以便比對。

### 4.3 與既有策略的重疊檢查（避免同一天出兩張近乎相同的名單）

| 既有策略 | 重疊點 | 差異 | 處置 |
|---|---|---|---|
| `chip_bottom_turnover`（籌碼） | C5、C6 幾乎相同 | 本策略多了 C1 估值、C2 營收、C3/C4 超跌 → **是它的嚴格子集** | 兩者皆保留：籌碼版負責「任何位階的洗盤」，本策略負責「低估值＋超跌的洗盤」。需實測重疊率（§11 AC-5） |
| `extreme_bias`（技術） | C3 門檻相同（−15%） | `extreme_bias` 是跨越式、單條件，會在下跌**途中**觸發 | 保留。定位不同：`extreme_bias` 是「注意」，本策略是「可買」 |
| `pick_valuation_low_pe`（選股） | C1 幾乎相同 | 該策略**只有**估值條件，無技術與籌碼守衛 | 保留。若實測名單重疊率過高，優先調整本策略的 C3/C4，不砍既有策略 |
| `kd_oversold_golden_cross`（技術） | C4 相近 | 該策略要求「季線之上」的超賣反彈（`trend_guard: require_above`），與本策略「季線下 −15%」互斥 | 天然互斥，無須處置 |

### 4.4 分階段交付

| 階段 | 內容 | 前置條件 |
|---|---|---|
| **P0** | §4.2 的 C1~C6 全部（皆可用現有資料與指標算出） | 全市場估值／營收已落地、`DATA_SOURCE=postgres` |
| **P1** | 加入**估值分位數**（PE 或 PB 位於近 3 年 ≤ 20% 分位），取代或並用 C1 的絕對門檻 | §6 的估值歷史回補完成 |
| **P2** | 型態辨識：二次探底（第二低點不破前低 `x%`）、下影線比例 ≥ `y`、頸線突破；結構性停損（進場 K 棒最低點）；季線正乖離停利 | 需先定義可計算規則，並另立指標規格 |
| **P3** | RSI 指標（若審核後仍認為 KD 不足以替代） | 另立指標規格文件 |

> **P0 的自我限制**：沒有分位數，C1 就是**跨產業的絕對門檻** —— `pe_max: 15` 對金融、傳產寬鬆，對半導體、生技幾乎不可能成立。P0 名單**必然偏向低估值產業**，這是已知且可接受的偏誤，P1 完成後才會改善（見 §13 Q-1）。

### 5.3 P1 需新增（估值分位數）

```
@condition(type="valuation_percentile", min_bars=1, requires=("valuation_history",))
```

- `ScanContext` 需新增 `valuation_history`（或由 repository 直接回傳每檔算好的分位門檻）。**不能沿用 `indicators/chip.rolling_percentile()`** —— 該函式只吃 `raw_records`（每日籌碼記錄），估值序列在 `ctx.valuation`，資料結構不同。

## 8. 出場與風控需求

### 8.1 沿用既有出場策略

| 需求 | 既有策略／條件 | 現值 |
|---|---|---|
| 固定停損 | `exit_fixed_stop_loss`（`fixed_stop_loss`） | `stop_loss_pct: 8.0` |
| 移動停利 | `exit_trailing_stop`（`trailing_stop`） | `drawdown_pct: 10.0` |
| 時間停損 | `time_stop` 條件已實作，但**尚未在 YAML 啟用** | `max_holding_days`／`min_return_pct` |

### 8.2 對 v1.0 風控數值的修正

| v1.0 | 判定 | 修正 |
|---|---|---|
| `hard_stop_loss_pct: -0.06` | ⚠️ | 與既有 8% 不一致、單位不一致（§2.2-5），且**無法只對本策略生效**（§8.3）。建議沿用既有 8%；若堅持 6%，等於全部持倉一起改 |
| `time_stop_days: 5` | ❌ | **過短**：融資洗盤後的打底期常以「週」計，5 個交易日未反彈就出場會把多數正確訊號洗掉。建議 20~40 個交易日，且必須搭配 `min_return_pct` |
| `trailing_stop_pct: 0.08` | ⚠️ | 與既有 10% 不一致；低檔承接標的波動大，8% 回檔容易被雜訊掃出。建議沿用 10% |
| `take_profit_bias_ma60: 10.0` | ❌ | **無對應條件函式**（`conditions_risk.py` 只有 `trailing_stop`／`fixed_stop_loss`／`time_stop`）。若要「季線正乖離 +10% 停利」，須新增 `bias_take_profit` 條件 → 列 P2 |

### 8.3 已知架構限制（需求上必須接受，或另立需求）

1. **出場規則無法依進場策略區分**：`scan_positions()` 對所有持股套用所有 `category ∈ {risk, fundamental}` 的策略。若要「本策略買進的部位用 6% 停損、其他用 8%」，需在持倉記錄保存 `entry_strategy_id` 並讓出場條件讀取 —— 屬 `portfolio_ledger` 與 `conditions_risk` 的共同擴充，**列 P2，不在 P0 範圍**。
2. **結構性停損不支援**：`fixed_stop_loss` 只算 `avg_cost` 的百分比，無法用「進場 K 棒最低點」。同列 P2。
3. **分批加碼不由引擎執行**：見 §2.1-11 與 ADR-RL-06。

| 需求 | 規格 | 依據／限制 |
|---|---|---|
| 每日名單上限 | `max_picks_per_day: 10` | `scanner.py` 依 `(strategy_id, trade_date)` 分組截斷 |
| 排序 | `sort_by: "dividend_yield"` → 殖利率高者優先 | **限制**：`_extract_sort_metric()`（`scanner.py:99`）只用**子字串**比對 `pe`／`yield`／`yoy`／`chip`／`ratio`，其他字串一律回傳 `0.0`（等同不排序）；且比對順序上 `pe` 最先 —— 任何**含 "pe" 的欄位名**（如 `pe_percentile`）都會落入 PE 分支。P1 若要用分位數排序，須先擴充此函式 |
| 排序方向 | 恆為 ascending，「越大越好」的欄位在 metric 內取負值 | 同上函式；新增排序欄位務必比照處理 |
| 冷卻 | `cooldown_days: 20` | 底部條件會連續多日成立；全域 `ALERT_COOLDOWN_DAYS` 太短會讓同一檔天天上榜。**只有截斷後真正入選的標的才寫入冷卻**（既有行為） |
| 去重 | `(symbol, strategy_id, direction, trade_date)` | 既有機制，無須新增 |

## 10. 通知與前端顯示需求

### 10.1 建議動作文案（`_suggested_action`）

需在 `scanner._SUGGESTED_ACTION_TEMPLATES` 登記 `("pick_relative_low_zone", "bullish")`，文案須反映**右側確認＋分批**的操作語意，例如：

> 已帶量站回 {ma_period}MA，可分批建立第一筆部位（建議 1/3），跌破 {stop_loss} 停損。

模板只支援 `{ma_period}`／`{stop_loss}` 兩個佔位符，且 `stop_loss` 由 `details["ma_value"] × 0.97` 推算 → `details` 必須提供 `ma_period` 與 `ma_value`（即 MA20 值），否則會填成 `—`。

## 12. 決議事項（ADR）

### ADR-RL-01：AND 組合寫在單一複合條件內，不新增組合器
沿用《選股爬蟲》ADR-SP-06。`scanner` 對多條件是 OR，新增「AND 組合器」會動到掃描核心並影響既有全部策略，風險不成比例。

### ADR-RL-02：以 KD 取代 RSI，不為本策略新增指標
KD 已實作、已驗證、已有超賣策略在跑，且與 RSI 在「超賣」語意上高度重疊。為單一策略新增指標會增加指標層維護面積（且須遵守「後端指標與前端等值實作保持一致」的既有慣例）。若日後有多個策略都需要 RSI，再另立指標規格。

### ADR-RL-03：右側確認（C6）是必要條件，不得降級為濾網
`filters.py` 的濾網只影響 `signal_strength`，不擋訊號。把「帶量站回 MA20」放濾網，等於策略退化成左側接刀 —— 與《極端抄底》定位重疊，且失去本策略存在的理由。

### ADR-RL-04：P0 用絕對估值門檻，分位數延後至 P1
估值歷史只有 3 個月，硬做分位數只會得到「近 3 個月的分位數」—— 那是雜訊，不是估值河流圖。寧可先上線偏誤已知的絕對門檻，也不要上線看似正確的假分位數。

### ADR-RL-05：不引入《極端抄底》的大盤環境鎖
本策略定位為常態選股，加上大盤鎖會讓它一年只有數天可用，與「每日名單」的產品語意衝突。大盤崩盤情境由《極端抄底》負責。

### ADR-RL-06：分批加碼與資金配置不進策略引擎
引擎只負責發訊號；部位大小與加碼節奏由人工決定並記在 `portfolio_ledger`。在引擎內表達資金權重會產生「系統以為的部位」與「實際部位」兩套真相。
