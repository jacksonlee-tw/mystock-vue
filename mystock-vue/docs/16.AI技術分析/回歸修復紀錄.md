**修復範圍**：後端 10 個檔案（前端經逐一比對後確認無損失）
**發現經過**：開發 [Phase2-籌碼面與基本面量化擴充](Phase2-籌碼面與基本面量化擴充.md) 時，發現

## 1. 問題性質

`27a7f96` 的 commit 訊息是「左邊menu功能tree調整」，實際卻異動 **34 個檔案**，其中多個後端核心檔案
被換成**功能較舊的版本**，同時又夾帶了合法的新工作（`core/owner_auth.py` 授權重構、左側選單樹、
指數抓取排序、4 個新測試檔）。典型特徵：

- 大量**純刪除**（`config.py` −166／+0、`db/models.py` −117／+0、`requirements.txt` −16／+0）
- 被刪掉的多半是**中文說明註解與 docstring**——本專案以註解為權威規格（見 CLAUDE.md），
  這種「程式碼留下、註解整批消失」的形狀，是從舊版重新產生檔案的痕跡，不是正常重構
- 後續兩個 commit（`6fb4759`、`3653da3`）已在不知情下**局部補回**部分功能
  （`get_latest_quote()`、`kind='index'`、`config.py` 常數），但沒有補回註解，也沒發現其餘缺口

**判定原則**：凡「舊版有、現版無，且無替代實作」者視為回歸並復原；凡有替代實作者
（如 `notify/security.py` 的擁有者授權 → `core/owner_auth.py`）視為合法重構，予以保留。

## 5. 建議後續處理

1. **重新安裝依賴**：`pip install -r backend/requirements.txt`——修復前的環境可能缺上述 12 個套件
   （現行執行中的環境因為是舊環境延續，套件其實還在，但全新部署會失敗）。
2. **檢查 `backend/.env`**：目前只有 12 個鍵，缺 `AI_ANALYSIS_ENABLED`／`CLAUDE_API_KEY`／
   `GEMINI_API_KEY`／`TW_SCHEDULE_TIME` 等。`.env` 未納版控無法追查是否同時受損，請對照已修復的
   `.env.example` 自行補齊（AI 報告功能在 `AI_ANALYSIS_ENABLED` 未設時預設關閉）。
3. **重跑受影響期間的台股抓取**：`27a7f96`（08-29 13:27）之後由排程或手動觸發寫入的三大法人
   買賣超，**賣超張數可能每筆少算 1 張**（`// 1000` bug）。建議對該期間以 `mode=repair` 重抓。
4. **檢視 commit 流程**：本次問題的根源是一個 commit 同時包含「新功能」與「大範圍舊版覆蓋」，
   且訊息只描述了新功能。建議往後 commit 前先看 `git diff --stat`，對「純刪除且集中在註解」的
   檔案特別留意。
