## 1. 現況盤點

### 1.1 目前具備的能力

| 項目 | 現況 |
|---|---|
| 涵蓋市場 | 僅台股（TWSE 上市），3 檔標的（`0050`、`2330`、`006208`） |
| 資料維度 | 外資 / 投信 / 自營商 / 合計買賣超（張）、收盤價、估算買賣超金額 |
| 資料來源 | TWSE `T86`（三大法人）、TWSE `STOCK_DAY`（收盤價） |
| 時間範圍 | 近 3 個月（`MONTHS_RANGE = 3`） |
| 儲存格式 | `data/{股票代號}.json`（key = 日期）+ 每次執行的 CSV 快照 |
| 呈現 | 單一離線 HTML，含下拉選單切換股票、三張 SVG 圖表、深淺色模式 |
| 容錯 | 已抓日期自動跳過、收盤價 0 值自動回補、逐日 3 秒延遲 |

### 1.2 已識別的缺口

| # | 缺口 | 影響 |
|---|---|---|
| G1 | **只有籌碼面單一維度**，缺少 OHLCV（開高低收量），無法計算任何技術指標 | 無法做均線、MACD、RSI、量價等絕大多數策略 |
| G2 | 資料來源與 TWSE **強耦合**，無資料源抽象層 | 無法接上櫃（TPEx）、美股、其他 API |
| G3 | 無「指標計算層」與「策略訊號層」 | 只能看圖用肉眼判斷，無法自動掃描、無法回測 |
| G4 | `plot_chart.py` 近 30KB 單檔，HTML/CSS/JS 全部以字串內嵌 | 難以維護與擴充新圖表類型 |
| G5 | 缺 `requirements.txt` / 相依版本鎖定 | 換機器或協作時環境不可重現 |
| G6 | CSV 快照直接寫在專案根目錄、且以日期命名不斷累積 | 目錄污染，且與 `data/` 職責重疊 |
| G7 | 無測試、無資料品質檢查（除了收盤價 0 的特例） | 上游格式變動只能靠執行時報錯才發現 |
| G8 | 無排程機制，需手動執行 | 資料新鮮度靠人工維持 |
| G9 | `MONTHS_RANGE` 為全域常數，抓取與繪圖範圍綁死 | 長期回測需要數年資料，但圖表只想看近 3 個月，兩者需求衝突 |
| G10 | 無「基準指數」資料（加權指數 / S&P 500） | 無法計算相對強弱、超額報酬、Beta |

## 2. 目標架構

建議改為四層架構，每層可獨立測試、獨立替換：

```
┌──────────────────────────────────────────────────────────┐
│  L4 呈現層 Presentation                                   │
│  互動圖表 HTML / 選股掃描報表 / 每日摘要 / 告警通知         │
├──────────────────────────────────────────────────────────┤
│  L3 策略層 Strategy                                       │
│  策略定義（進出場規則）→ 訊號產生 → 回測 → 績效統計         │
├──────────────────────────────────────────────────────────┤
│  L2 指標層 Indicator                                      │
│  MA / MACD / RSI / KD / BBands / ATR / OBV / RS ...       │
│  純函式：DataFrame in → DataFrame out，可單元測試          │
├──────────────────────────────────────────────────────────┤
│  L1 資料層 Data                                           │
│  Provider 介面（TWSE / TPEx / TDCC / TAIFEX / yfinance /  │
│  SEC EDGAR / FRED ...）→ 正規化 → 本地快取（Parquet/DB）   │
└──────────────────────────────────────────────────────────┘
```

**核心設計原則**

- **Provider 介面統一**：不論資料來自 TWSE 或 Yahoo，對上層都回傳同一套欄位名稱（見 §8）。
- **抓取與分析解耦**：抓取只負責「補齊本地資料」，分析永遠讀本地，不觸網。
- **指標層零副作用**：純函式，不讀檔不發網路請求，方便寫測試。
- **策略以設定描述**：策略參數（均線天期、閾值）用 YAML/JSON 設定檔管理，新增策略不必改核心程式。

**台股 ETF 特別注意事項**

- **溢價風險**：台股熱門主題 ETF 曾出現雙位數溢價，G1 折溢價監控對台股 ETF 的重要性遠高於美股 ETF。
- **配息 ≠ 報酬**：高股息 ETF 需檢查配息是否來自「收益平準金」（本金），單看殖利率會失真。
- **還原報酬**：計算長期績效務必用**還原息值**的價格序列，否則除息當日會誤判為大跌。

### 8.2 統一欄位命名（Provider 正規化後的契約）

不同市場、不同來源的欄位一律轉成同一組英文欄位名，中文只在**呈現層**做對照，避免中文欄位名散落在計算邏輯中：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `date` | date | 交易日（統一 ISO 格式） |
| `open` / `high` / `low` / `close` | float | 開高低收（未還原） |
| `adj_close` | float | 還原股價（除權息調整後），**所有報酬率計算一律用此欄** |
| `volume` | int | 成交量（統一為「股數」，台股張數 ×1000，避免單位混淆） |
| `turnover` | float | 成交金額（原幣別） |
| `market` | str | `TW` / `US` |
| `asset_type` | str | `stock` / `etf` |
| `currency` | str | `TWD` / `USD` |

籌碼／基本面等非價量資料，各自獨立成表（`institutional`、`margin`、`revenue`、`holdings`…），以 `(symbol, date)` 為主鍵，需要時才 join，不要把所有欄位塞進同一張寬表。

### 8.3 儲存格式建議

| 現況 | 建議 | 理由 |
|---|---|---|
| `data/{代號}.json`（key = 日期） | `data/curated/{market}/{symbol}.parquet` | JSON 在資料量成長到數年 × 數十檔後讀取與體積都吃虧；Parquet 有型別、壓縮率高、pandas 原生支援 |
| 專案根目錄的日期 CSV 快照 | 移入 `data/raw/`，並加保留天數清理 | 避免根目錄污染（缺口 G6） |
| 無中繼資料 | 每個 symbol 附一份 `_meta.json`（最後更新時間、來源、資料筆數、缺漏日期） | 資料品質可追蹤，也讓增量抓取更精準 |

> 若希望維持 JSON 的可讀性，折衷做法：`raw` 保留 JSON、`curated` 用 Parquet。

## 10. 風險、限制與注意事項

### 10.1 資料面

| 風險 | 說明 | 因應 |
|---|---|---|
| **官方端點格式變動** | TWSE 曾把 `STOCK_DAY_ALL` 由 JSON 改為 CSV | Provider 層集中處理格式；加入 schema 檢查，格式不符即告警而非默默寫入錯誤資料 |
| **節流與封鎖** | TWSE 長時間高頻請求會開始逾時（README 已記錄實測） | 維持延遲、增量抓取、失敗重試與退避；長歷史資料一次抓完後只做增量 |
| **yfinance 非官方** | Yahoo 隨時可能改介面或限流 | 必備備援（Stooq），Provider 介面讓切換成本趨近於零 |
| **還原股價陷阱** | 除權息造成的「假跌」會讓所有技術指標失真 | 一律以 `adj_close` 計算報酬與指標；`close` 只用於顯示 |
| **前視偏誤（Look-ahead bias）** | 月營收 10 日才公布、13F 延遲 45 天，若用「當月」對齊會嚴重高估回測績效 | 每筆基本面資料同時記錄「資料期間」與「**實際公布日**」，回測一律以公布日對齊 |
| **倖存者偏誤** | 只追蹤現存標的，會忽略下市／清算的 ETF 與個股 | 回測時 universe 需包含歷史成分（此為長期議題，初期先明確記錄限制） |

### 10.2 策略面

- **參數過度最佳化**：41 個策略若各自調參，極易 overfit。建議固定用業界慣用參數（如 RSI 14、MACD 12/26/9），只在必要時做穩健性測試（參數高原而非參數尖峰）。
- **市場差異**：台股有漲跌幅限制（10%）與 T+2 交割，美股無漲跌幅限制且有盤前盤後——同一套參數在兩市場的表現不可直接比較。
- **ETF 不適用個股邏輯**：ETF 沒有「內部人」「營收」，且分散持股使技術訊號較個股鈍化；不要把個股策略無差別套用到 ETF。
- **籌碼面資料的時效**：三大法人是**收盤後**公布，D 類策略最快只能在隔日開盤執行，回測須據此設定進場價。

### 10.3 合規與使用限制

- 各資料源的使用條款不同（尤其第三方 API 對「重新散布」多有限制），若日後要公開分享資料檔需先確認授權。
- 官方開放資料（TWSE / TPEx / TDCC / SEC / FRED）多為公眾可用，但仍應遵守其請求頻率規範。
- 本專案為個人研究與資料視覺化工具，**不構成投資建議**；策略訊號僅為研究輸出，實際交易決策與風險由使用者自負。
