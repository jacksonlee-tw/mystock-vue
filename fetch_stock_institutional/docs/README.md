# fetch_stock_institutional

抓取台灣證券交易所（TWSE）公開資訊中，指定個股的「三大法人買賣超」「融資融券餘額」
「每日行情」資料，將歷史資料累積成 JSON 檔，並自動繪製互動式趨勢圖。

## 目錄結構

```
fetch_stock_institutional/
├── main.py                       # 主程式進入點：預設只「繪圖」，加 --fetch 才先「抓取」
├── institutional_fetcher.py       # 抓取邏輯：向 TWSE 抓資料、存成 CSV + 依股票代號分檔的 JSON
├── plot_chart.py                  # 掃描 data/*.json，產生可切換股票的互動式曲線圖 HTML
├── .env                            # 追蹤股票代號設定（STOCK_CODES，不進版本控制）
├── .env.example                    # .env 範本
├── data/
│   ├── 0050.json                   # 0050 的歷史資料（institutional_fetcher.py 產生/合併）
│   ├── 2330.json                   # 2330 的歷史資料
│   ├── 006208.json                 # 006208 的歷史資料
│   └── _no_trading_days.json       # 已確認無交易資料的日期快取（底線開頭，plot_chart.py 會略過）
├── chart/
│   └── institutional_chart.html    # 圖表輸出檔（plot_chart.py 產生）
├── 個股三大法人買賣超_YYYYMMDD.csv    # 每次抓取的當次快照 CSV
└── docs/
    └── README.md                   # 本文件
```

**職責劃分**：`main.py` 保持精簡，只負責「解析參數 → 視情況呼叫抓取 → 呼叫繪圖」；
實際的抓取邏輯全部搬到 `institutional_fetcher.py`；繪圖邏輯維持在 `plot_chart.py`。
三者可獨立執行，也可透過 `python main.py --fetch` 一次跑完全部流程。

## 環境需求

- Python 3.9+
- 套件：`requests`、`pandas`、`python-dotenv`（標準函式庫 `json` / `os` / `time` /
  `datetime` / `calendar` / `glob` / `re` 無需另外安裝）

```bash
pip install requests pandas python-dotenv
```

## 設定要追蹤的股票（.env）

欲追蹤的股票／ETF 代號清單設定在 `.env` 的 `STOCK_CODES`（逗號分隔），**不用改
程式碼**即可隨時增減：

```dotenv
STOCK_CODES=0050,2330,006208
```

第一次使用請先複製範本：

```bash
cp .env.example .env
```

`.env` 已加入 `.gitignore`，不會被提交進版本控制；`.env.example` 則作為團隊共用的
範本保留。若 `.env` 不存在或 `STOCK_CODES` 為空，`institutional_fetcher.py` 會回退
使用內建的 `DEFAULT_STOCKS`（`get_target_stocks()`）。

## 使用流程

```bash
cd fetch_stock_institutional
python main.py            # 只用現有資料重新產生圖表（預設，不連線抓資料）
python main.py --fetch    # 先抓取最新資料，再產生圖表（-f 為縮寫）
```

**預設不抓資料。** 抓取會連線證交所、耗時且有頻率限制，而重畫圖表完全不會動到
`data/`，因此要抓資料必須明確加上 `--fetch`。

**唯一的例外：`.env` 新增了從未抓過的股票。** 啟動時會比對 `STOCK_CODES` 與
`data/` 下的資料檔，若有股票完全沒有資料（圖表上根本畫不出來），會先問過再決定：

```text
$ python main.py
🆕 偵測到 1 檔股票尚未抓過資料：2317
   （.env 的 STOCK_CODES 有設定，但 data/ 下沒有對應的資料檔，圖表上會缺這幾檔）
❓ 是否要現在抓取資料？(y/N)
```

輸入 `y` / `yes` 才會抓；其他輸入（含直接按 Enter）都當作否，直接用現有資料繪圖。

`main.py` 的執行步驟：

1. `institutional_fetcher.fetch_and_save()` — 加了 `--fetch`，**或**上述詢問回答
   `y` 時才執行；抓取三大法人資料，存成 CSV 快照 + 依股票代號分檔的 JSON。
2. `plot_chart.main()` — 一律執行；讀取最新的 `data/*.json`，重新產生
   `chart/institutional_chart.html`。

> 回答 `y` 時抓的是 `.env` 的**完整清單**，不是只抓新股票。因為 T86 是全市場的
> 單日快照，只抓新股票的請求次數完全一樣，卻會錯過順便補齊其他股票缺漏日期的機會。

排程／管線等非互動環境（`stdin` 不是終端機）不會卡在等輸入——會印出提示後視同
「否」繼續繪圖，所以自動化流程要抓資料請明確加上 `--fetch`。

執行完成後，以瀏覽器開啟 `chart/institutional_chart.html` 即可查看圖表——該檔案
為單一 HTML、不依賴任何外部 CDN，可離線開啟。

也可以單獨執行其中一步：

```bash
python institutional_fetcher.py   # 只抓資料，不畫圖
python plot_chart.py              # 只依現有資料重畫圖，不重新抓取（等同於不加參數的 main.py）
```

## `main.py`：主程式進入點

刻意保持極簡，不包含任何抓取/繪圖細節，只做「參數解析 + 詢問 + 流程串接」：

```python
def main(argv=None):
    args = parse_args(argv)                                   # 目前只有 -f / --fetch
    should_fetch = args.fetch or confirm_fetch_for_new_stocks()
    if should_fetch:
        institutional_fetcher.fetch_and_save()
    plot_chart.main()
```

| 指令 | 情境 | 抓取資料 | 產生圖表 |
|---|---|---|---|
| `python main.py` | `.env` 股票都有資料 | ✗（不詢問） | ✓ |
| `python main.py` | `.env` 有沒抓過的股票，答 `y` | ✓ | ✓ |
| `python main.py` | `.env` 有沒抓過的股票，答其他 | ✗ | ✓ |
| `python main.py --fetch`（或 `-f`） | 任何情境 | ✓（不詢問） | ✓ |

「哪些股票沒抓過」由 `institutional_fetcher.find_stocks_without_data()` 判定
（`data/{股票代號}.json` 不存在或內容為空），詢問的互動則留在 `main.py`。

`python main.py --help` 可列出說明。若要調整「抓取」或「繪圖」的行為，應修改
`institutional_fetcher.py` 或 `plot_chart.py`，而不是 `main.py`。

## `institutional_fetcher.py`：資料抓取模組

### 功能

核心進入點是 `fetch_and_save(target_stocks=None, months=MONTHS_RANGE)`：

1. 決定股票清單（未指定時取自 `.env` 的 `get_target_stocks()`）與日期範圍
   （`months_ago(MONTHS_RANGE)` 依日曆月精確回推日期，換算成對應天數——**預設
   `MONTHS_RANGE = 3`，即近三個月**；不是固定 90/92 天，而是依實際月份天數計算，
   例如 5/6 回推 3 個月會準確落在 2/6）。
2. `fetch_daily_quotes()` — 預先抓取每檔股票的每日行情（開高低收與成交量值，
   見下方「資料來源」）。
3. `fetch_stock_institutional_data(target_stocks, days, quote_lookup)` — 逐日抓取
   三大法人（T86）與融資融券（MI_MARGN）資料，行情直接查上一步的結果，
   不再逐日另外打價格端點。
4. 存成當次 CSV 快照，並呼叫 `save_data_to_json()` 依股票代號分檔、累積寫入 JSON。
5. `backfill_daily_quotes()` — 用剛抓到的行情，修補既有 JSON 中先前失敗留下的
   `0` 元佔位值，或本功能上線前留下、欠缺開高低量欄位的舊格式紀錄（見下方
   「已知限制」）。

執行時會印出實際套用的股票清單與日期區間，例如：

```text
🎯 追蹤股票（來自 .env STOCK_CODES）：['0050', '2330', '006208']
📅 資料範圍：近 3 個月（2026-05-06 ~ 2026-08-06）
```

**已抓過的「完整」日期會自動跳過，不重新發送 T86 / MI_MARGN 請求**：抓取前會先
讀取每檔股票既有的 `data/{股票代號}.json`，若某天所有 `target_stocks` 都已有
**T86 且已有融資融券**資料（`is_date_complete()` 以「這天的記錄裡有沒有
`融資餘額(張)` 這個 key」判斷），**或該日期已被確認是無交易資料的日子**（見下方
「執行時的容錯行為」），就直接略過那一天，完全不打 API、也不會觸發 3 秒延遲。
因此重複執行通常只需要抓取新增的 1 天，執行時間會遠短於第一次的完整抓取。

- 這個跳過判斷**只看 T86／MI_MARGN 資料是否存在，與行情無關**——行情的新鮮度
  改由 `fetch_daily_quotes()` + `backfill_daily_quotes()` 統一處理，不會為了
  修補行情而白白重抓一次 T86／MI_MARGN（兩者本身抓取穩定，不需要重試）。
- 只要有任何一檔目標股票缺這天的完整資料（例如新加入的股票尚無歷史，或是
  **本功能上線前抓過、只有 T86 沒有融資融券的舊記錄**），當天就會照常發送兩個
  請求（T86／MI_MARGN 都是全市場快照，不會只抓單一股票）——這代表**第一次
  套用本功能時，即使 `data/` 已有三大法人的歷史資料，仍會把近 `MONTHS_RANGE`
  個月的每一天重新抓一次**，用來補齊融資融券欄位（見下方「已知限制」的時間估算）。
- 查無融資融券資料的股票會在整輪執行結束後統一提示一次（而不是每天都印一次），
  例如：`⚠️ 以下股票在抓取範圍內查無融資融券資料，可能為上櫃股票（MI_MARGN
  信用交易報表僅涵蓋上市）：['6488']`——MI_MARGN 只涵蓋上市（TWSE）股票，
  上櫃（TPEx）股票需要另外串接對應報表，目前不在支援範圍內。
- 執行結束會印出這次總共跳過幾天，例如：
  `⏭️ 略過 42 天（目標股票皆已有完整資料，未發送任何請求）`

抓取的欄位：

- 開盤價／最高價／最低價／收盤價
- 成交股數（股）／成交金額（元）／成交筆數（筆）
- 外資／投信／自營商／三大法人合計買賣超（張）
- 估算買賣超金額（萬元）＝ 合計買賣超張數 × 收盤價 ÷ 10
- 融資買進／賣出／現金償還／前日餘額／今日餘額（張）
- 融券買進／賣出／現券償還／前日餘額／今日餘額（張）
- 資券互抵（張）

> ℹ️ 開盤／最高／最低／收盤價已用來繪製 K 線圖（見下方 `plot_chart.py` 章節）；
> 成交股數／成交金額／成交筆數目前仍只存進 JSON，尚未有對應圖表（成交量圖的
> 工作量與 K 線圖不同量級，先把資料存起來供未來使用）。融資融券只有「今日餘額」
> 與衍生的「券資比」有對應圖表，其餘明細欄位（買進／賣出／償還／前日餘額）
> 目前僅供存查。

### 資料來源（TWSE 公開 API）

| 端點 | 用途 | 頻率 |
|---|---|---|
| `https://www.twse.com.tw/rwd/zh/fund/T86` | 當日所有個股三大法人買賣超 | 逐日（全市場快照，已抓過的完整日期會跳過） |
| `https://www.twse.com.tw/rwd/zh/marginTrading/MI_MARGN?selectType=ALL` | 當日所有個股融資融券彙總 | 逐日（全市場快照，與 T86 併在同一個日迴圈，已抓過的完整日期會跳過） |
| `https://www.twse.com.tw/rwd/zh/afterTrading/STOCK_DAY?stockNo=...` | 單一股票、單一月份的每日行情（開高低收與成交量值） | **每檔股票、每個月份各一次**（`fetch_daily_quotes()`） |

> ℹ️ 行情原本也是逐日呼叫全市場的 `STOCK_DAY_ALL`（近 3 個月約 90 次請求），
> 但長時間高頻率請求容易被 TWSE 節流導致大量逾時（見下方「已知限制」的歷史紀錄）。
> 已改用 `STOCK_DAY`（單股單月），3 檔股票 × 3 個月僅需 9 次請求，大幅降低
> 觸發節流的機會。`STOCK_DAY` 回傳的日期是民國年格式（如 `"115/08/03"`），
> 由 `_roc_date_to_iso()` 轉換成西元 ISO 格式；同一次回應除了收盤價，也一併
> 解析開盤價、最高價、最低價、成交股數、成交金額、成交筆數（零額外請求成本）。
>
> ℹ️ `MI_MARGN` 回傳的結構是 `{"stat", "date", "tables": [...]}`，`tables[0]`
> 是全市場總量彙總（3 筆，用不到），`tables[1]` 才是逐股彙總（約 1,300 多筆，
> 含所有上市股票／ETF），已實測確認欄位順序（見 `_MI_MARGN_FIELD_MAP`）。

### 執行時的容錯行為

- 每個請求之間（T86 逐日、MI_MARGN 逐日、行情逐月）都強制 `time.sleep(3)` 秒，
  避免請求過於頻繁被 TWSE 封鎖——T86 與 MI_MARGN 是各自獨立的端點，即使併在
  同一個日迴圈裡也各自有自己的延遲，不會共用同一次 sleep。
- 遇到非交易日（例如國定假日），`T86` 會回傳 `stat != "OK"`，程式印出
  `⏸️ 無交易資料` 並跳過（`MI_MARGN` 對應天數不會重複印出同樣的訊息）；行情
  端點對應查無資料的月份則印出 `⏸️ {股票代號} {年}-{月} 無收盤價資料`。這是
  TWSE 官方回應「查無資料」（`stat` 訊息為「很抱歉，沒有符合條件的資料!」），
  並非程式錯誤——可用 `curl`／瀏覽器直接打相同網址驗證。
- 任何例外（逾時、JSON 解析失敗等）都會印出警告並繼續下一個項目，不會中斷整體
  執行；行情抓取失敗的股票/月份，其涵蓋的日期會維持 `收盤價 = 0` 的佔位值，
  留待下次執行時由 `backfill_daily_quotes()` 補上；融資融券抓取失敗或查無該
  股票資料時，當天記錄**不會補 0 佔位值**，而是刻意留空，讓 `is_date_complete()`
  在下次執行時判定「這天還不完整」而自動重試。
- **確認無交易資料的日期會被快取**：`T86` 回傳「查無資料」時（且該日期早於
  「今天」——今天的資料可能只是還沒公布，永遠不會被快取），會記錄到
  `data/_no_trading_days.json`。下次執行時，這些日期會和「已有完整資料的日期」
  一樣直接跳過，不再重新查詢——國定假日不會每次執行都重新確認一次。
  （`plot_chart.py` 掃描 `data/*.json` 時，檔名以底線開頭的檔案一律略過，
  不會被誤判成股票資料。）
- **抓取過程會持續印出進度**，避免長時間安靜等待：行情預先抓取階段
  （`fetch_daily_quotes()`，通常是唯一有感等待時間的部分）會逐筆印出
  `[目前次數/總次數] 股票代號 年-月 ...`，完成後補上結果；T86／MI_MARGN 逐日
  抓取階段本來就會逐日印出 `✅ 成功抓取` / `⏸️ 無交易資料` / `❌ 抓取失敗`。

### 輸出

1. **CSV 快照**：`個股三大法人買賣超_YYYYMMDD.csv`（本次執行抓到的所有資料，
   `utf-8-sig` 編碼，Excel 可直接開啟；路徑固定在 `institutional_fetcher.py`
   所在目錄，與執行時的工作目錄無關）。
2. **依股票代號分檔的累積式 JSON**：`data/{股票代號}.json`（例如 `data/2330.json`、
   `data/0050.json`），由 `save_data_to_json()` 寫入，回傳本次寫入的檔案路徑清單。
   - `target_stocks` 清單中的每一檔股票都會各自存成獨立檔案，檔名即為股票代號
     （`stock_json_path()` 統一產生路徑），方便日後單獨備份、分享或刪除單一個股的資料。
   - 每個檔案都會先讀取既有內容再合併，讓每次執行都能**累積歷史資料**
     （相同日期以最新一次抓取結果**逐欄位合併**，其餘既有日期保留）。逐欄位
     合併而非整筆覆蓋，是為了避免這種情況：某次重抓當天資料時，若其中一個
     資料來源恰好失敗（例如 `MI_MARGN` 逾時，但 `T86` 成功），這次組出的
     記錄就不會包含融資融券欄位——若用整筆覆蓋，會把既有記錄裡先前已經
     抓到的融資融券資料一併清空；改用逐欄位合併後，只有這次實際抓到的
     欄位會被更新/新增，既有欄位維持不變。
   - 結構（key 為 **日期**；股票代號已由檔名表示，不再重複出現於內容中）：

     ```json
         "成交筆數(筆)": 45678,
         "外資買賣超(張)": -4012,
         "投信買賣超(張)": 0,
         "自營商買賣超(張)": -83,
         "合計買賣超(張)": -584,
         "估算買賣超金額(萬元)": -138116.0,
         "融資買進(張)": 1073,
         "融資賣出(張)": 331,
         "融資現金償還(張)": 19,
         "融資前日餘額(張)": 29226,
         "融資餘額(張)": 29949,
         "融券買進(張)": 27,
         "融券賣出(張)": 3,
         "融券現券償還(張)": 0,
         "融券前日餘額(張)": 62,
         "融券餘額(張)": 38,
         "資券互抵(張)": 0
       },
       "2026-08-05": { "...": "..." }
     }
     ```

     融資融券欄位（`融資買進(張)` ~ `資券互抵(張)`）只在當天實際抓到 `MI_MARGN`
     資料時才會出現，查無資料的日子會缺這幾個 key（而不是補 0）——這是刻意
     設計，用來讓 `is_date_complete()` 能正確判斷「這天還缺融資融券」並在下次
     執行時自動重試（見上方「執行時的容錯行為」）。次一營業日限額、註記兩個
     `MI_MARGN` 原始欄位刻意不存：前者是主管機關給的額度上限而非交易結果，
     後者是文字備註，兩者都對走勢分析沒有意義。

### 如何調整抓取範圍 / 追蹤股票

- **抓取天數範圍**：修改 `institutional_fetcher.py` 上方的常數即可
  （`plot_chart.py` 會一併沿用，兩者的抓取/繪圖範圍恆保持一致）：

  ```python
  MONTHS_RANGE = 3   # 改成 6 即為近半年、12 即為近一年 ...
  ```

- **追蹤股票清單**：編輯 `.env` 的 `STOCK_CODES`（見上方「設定要追蹤的股票」），
  **不需修改程式碼**、可自由增減多檔股票，每一檔都會各自產生一個
  `data/{股票代號}.json`。找不到 `.env` 或未設定時，回退使用
  `institutional_fetcher.py` 內的 `DEFAULT_STOCKS` 常數。

  新增一檔股票後直接執行 `python main.py` 即可——它會發現這檔還沒有資料並詢問
  是否抓取（見上方「使用流程」），不必特地記得加 `--fetch`。

## `plot_chart.py`：圖表產生程式

### 功能

掃描 `data/` 目錄下**所有**個股 JSON 檔（`discover_stock_files()`：檔名即股票代號，
例如 `data/2330.json` → 股票代號 `2330`），針對每一支股票各繪製六張互動式曲線圖，
輸出成單一離線 HTML 檔（`chart/institutional_chart.html`），並以**下拉選單**切換要顯示
哪一檔股票（不會把所有股票的圖表全部堆疊在同一頁）：

- 非「日期: {...}」格式的檔案（例如手動放進去的其他 JSON）會被自動略過並印出警告，
  不會中斷繪圖。
- 繪圖範圍與 `institutional_fetcher.py` 共用同一個 `MONTHS_RANGE`（預設近 3 個月，
  透過 `from institutional_fetcher import DATA_DIR, MONTHS_RANGE, months_ago` 沿用，
  避免重複定義）。`load_all_stocks_data()` 會以 `months_ago(MONTHS_RANGE)` 算出
  截止日期，只保留該日期（含）之後的資料再繪圖——即使個別檔案因長期累積而存有
  更久遠的歷史，圖表仍只顯示近期範圍。
- 頁首會顯示實際套用的日期區間，例如：
  `資料來源：data/*.json ・ 範圍：近 3 個月（2026-05-06 ~ 2026-08-06）・ 產生時間：...`
- 下拉選單的股票順序固定依**檔名排序**（透過內嵌的明確順序陣列 `order`，不依賴
  JavaScript 物件的 key 走訪順序——後者會把「看起來像正整數」的代號如 `2330`
  自動排到帶前導零的代號如 `0050` 之前，順序不可預期，因此特別繞開這個坑）。
- 只有一檔股票資料時，選單會自動隱藏（此時沒有切換的必要）。

每檔股票各自繪製：

1. **三大法人買賣超（張）** — 外資 / 投信 / 自營商 / 合計，共用同一 Y 軸（單位一致），
   含 0 基準線。
2. **K 線圖（蠟燭圖）** — 以開盤／最高／最低／收盤價繪製，**紅漲綠跌**（台股慣例，
   與美股紅跌綠漲相反）；查無行情資料的日子留白、不畫蠟燭；圖例標示「上漲／
   下跌」兩色。這是獨立於折線圖之外的另一種繪製邏輯（`renderCandlestickChart()`），
   不共用 `renderLineChart()` 的實作。
3. **估算買賣超金額（萬元）** — 單一序列折線圖，含 0 基準線。
4. **融資餘額（張）** — 單一序列折線圖。
5. **融券餘額（張）** — 單一序列折線圖，刻意與融資餘額分開兩張卡片而非雙 Y 軸
   （兩者量級差很多，融資餘額常是萬張等級、融券餘額常是百張等級，同軸畫會讓
   融券那條線幾乎貼著 0；本站的圖表一律不使用雙 Y 軸）。
6. **券資比（%）** — 融券餘額 / 融資餘額，衍生指標、不落地存成 JSON 欄位，由前端
   在聚合後即時算出；融資餘額為 0（無融資融券資料，或真的沒有融資）的時間點
   會顯示為缺值、折線在該處斷開，而不是誤顯示成「券資比 0%」。

成交量值（成交股數／成交金額／成交筆數）已存進 JSON，但目前**沒有對應圖表**
（成交量圖工作量與 K 線圖不同量級，先把資料存起來供未來使用）。融資融券的
買進／賣出／償還／前日餘額等明細欄位也已存進 JSON，同樣目前只有「今日餘額」
與「券資比」有對應圖表。

### 週期聚合規則（日線／週線／月線）

資料一律以「日」為單位夾帶在 HTML 內，週線／月線由前端 JS 即時聚合，切換週期
不需要重新產生檔案。依欄位性質分五種聚合方式（`plot_chart.py` 內嵌 JS 的
`SUM_FIELDS` / `END_FIELDS` / `START_FIELDS` / `MAX_FIELDS` / `MIN_FIELDS`）：

- **流量欄位（加總，`SUM_FIELDS`）**：買賣超張數、估算買賣超金額——一週的
  買賣超是五個交易日的加總。
- **存量欄位（取期間最後一筆有效值，`END_FIELDS`）**：收盤價、融資餘額、
  融券餘額——一週的融資餘額是**週五那天的餘額**，不是五天相加。這是最容易
  寫錯的地方：若誤用加總邏輯，週線的餘額會變成日餘額的數倍，趨勢形狀還是對的、
  數值卻整個錯誤，不容易一眼看出問題。
- **K 線圖開盤價（取期間第一筆有效值，`START_FIELDS`）**：一週的開盤價是
  **週一的開盤價**。
- **K 線圖最高／最低價（`MAX_FIELDS` / `MIN_FIELDS`）**：一週的最高價是五天
  最高價中的最大值、最低價是五天最低價中的最小值——**不是週五那天的最高低價**。
  最低價的聚合特別要小心：0 是「查無資料」的佔位值，若直接取 `Math.min` 會被
  0 拉低，`aggregateStock()` 內是手動忽略 0 才取最小值。
- **衍生指標（聚合後才計算）**：券資比在聚合出當週／當月的期末融資、融券餘額
  之後才相除計算，不是對每日券資比取平均——後者沒有金融意義。

### 圖表功能

- 選單上方一列固定放置「股票」下拉選單，切換後即時顯示對應股票的六張圖表；
  上方「圖表快速連結」可直接跳轉到對應卡片。
- 滑鼠移動 / 鍵盤方向鍵（←/→）皆可觸發十字線 + tooltip，顯示當日各序列數值；
  缺值（例如券資比的除零保護、K 線圖查無行情的日子）顯示為「—」。
- 圖例（≥2 個序列時顯示），顏色依固定順序配色（不因篩選而重新配色）；K 線圖
  的圖例固定顯示「上漲／下跌」兩色，不隨股票而變。
- 每張圖下方皆有「顯示資料表」按鈕，展開精確數值表格（無障礙備援，避免資訊只能靠
  顏色或 hover 取得）；K 線圖的資料表欄位是開／高／低／收四欄。
- 支援淺色 / 深色模式：自動跟隨系統設定，亦可點擊右上角 🌓 按鈕手動切換。
- 純前端 Vanilla JS + inline SVG 產生，不依賴任何外部套件或網路連線，
  產生的 HTML 可直接分享或離線開啟（所有股票的資料皆內嵌於同一檔案中，切換選單
  只是切換顯示/隱藏，並非重新讀取檔案）。

### 執行方式

```bash
python plot_chart.py
```

- 若 `data/` 目錄下找不到任何個股 JSON 檔，會印出提示訊息並中止。
- 輸出路徑固定為 `plot_chart.py` 同層 `chart/` 子目錄下的 `institutional_chart.html`
  （目錄不存在時會自動建立）。

### 如何客製化圖表

- 修改 `plot_chart.py` 頂部匯入的 `DATA_DIR`（沿用自 `institutional_fetcher.py`）
  可指向不同資料目錄。
- 若要新增/移除**折線圖**序列（例如把成交量畫成圖），需同步調整：
  1. `institutional_fetcher.py` 抓取並寫入 JSON 的欄位（成交量值已存在，見上方
     「輸出」的 JSON 結構）。
  2. `plot_chart.py` 的 `load_all_stocks_data()`（讀取欄位）。
  3. 依欄位性質加進對應的聚合分類：流量加進 `SUM_FIELDS`；存量（例如某種餘額）
     加進 `END_FIELDS`；若還需要「取期初值」或「取期間極值」（K 線圖以外的
     場景），可以仿照 `START_FIELDS` / `MAX_FIELDS` / `MIN_FIELDS` 的寫法新增。
     並在 `aggregateStock()` 的聚合迴圈與 `buildChartCard(...)` 呼叫中對應到
     圖表序列與圖例文字——**務必先確認新欄位的聚合方式**，用錯會產生「趨勢
     形狀正確、數值卻整個錯誤」的圖（見上方「週期聚合規則」）。
- 若要調整 **K 線圖**（例如疊加均線、改變蠟燭寬度規則），修改
  `renderCandlestickChart()`（繪製邏輯）與 `buildCandlestickCard()`（卡片組裝、
  圖例、資料表），兩者刻意獨立於折線圖的 `renderLineChart()` / `buildChartCard()`
  之外，互不影響。

## 已知限制

- TWSE 官方端點格式可能隨時調整，若日後遇到解析錯誤（例如 JSON 解析失敗、
  欄位順序改變），優先確認該端點目前實際回傳的 `Content-Type` 與內容格式，
  必要時對照 `institutional_fetcher.py` 內的欄位索引註解逐一核對。
- 抓取範圍以「今天」往回推算 `MONTHS_RANGE` 個日曆月（預設 3 個月）再排除週末，
  並未排除國定假日（會由 API 回傳 `stat != "OK"` 間接處理，僅印出提示、不會產生資料）。
- **只支援上市（TWSE）股票，不支援上櫃（TPEx）**：融資融券資料來源 `MI_MARGN`
  只涵蓋上市股票／ETF。若 `.env` 的 `STOCK_CODES` 加入上櫃代號，三大法人與
  收盤價仍會正常抓取，但融資融券欄位會持續缺漏，並在每次執行結束時印出
  提示（見上方「執行時的容錯行為」）。若未來需要支援上櫃，須另外串接 TPEx
  對應的信用交易報表，目前未實作。
- 目前預設追蹤 `0050`、`2330`、`006208` 三檔（見 `.env` 的 `STOCK_CODES`）；
  可自由增加更多股票。T86／MI_MARGN 請求次數只跟「天數」有關、與股票數無關
  （皆為全市場快照，近 3 個月各約 60 幾次，兩者相加約 120 次）；行情請求次數
  則是「股票數 × 月份數」（3 檔 × 3 個月 = 9 次），股票數增加只會線性微增，
  不會像早期版本那樣暴增。
  - **第一次套用融資融券功能**（即使 `data/` 已有三大法人的歷史資料）：因為
    `is_date_complete()` 要求「T86 且融資融券」都有資料才算完整，舊記錄只有
    T86、沒有融資融券，會被判定為不完整而整段重新抓取——約需 6～8 分鐘
    （T86 與 MI_MARGN 合計約 120 次請求 × 3 秒延遲），比只抓 T86 的年代久一倍。
  - **全新股票／全新環境的第一次完整抓取**：時間估算同上，`MONTHS_RANGE`
    加大會等比例增加執行時間。
  - 之後重複執行則會套用「已抓過的完整日期自動跳過」機制，通常幾秒內就能結束。

### 歷史問題（已修復）：`STOCK_DAY_ALL` 長時間執行會被節流

早期版本收盤價是逐日呼叫全市場的 `STOCK_DAY_ALL`（近 3 個月約 90 次請求、
持續 3～4 分鐘）。實測發現：持續高頻率請求一段時間後，該端點幾乎每一天都
`Read timed out`，但同一個網址在批次結束後單獨呼叫卻能秒回——顯示這是 TWSE
針對「持續高頻率存取重量級端點」的節流機制，而非帳號或 IP 被封鎖。三大法人
張數本身不受影響（來自另一支端點 `T86`），但收盤價與估算金額因此存成 `0`。

**現況**：已改用單股單月的 `STOCK_DAY`（見上方「資料來源」），請求量從 ~90
次降到 ~9 次，大幅降低觸發節流的機會。若既有資料中仍有 `收盤價 = 0` 的殘留
（例如舊版留下的），或欠缺開高低量欄位的舊格式紀錄（融資融券功能上線前留下
的），下次執行 `python main.py` 時 `backfill_daily_quotes()` 會自動用新抓到的
行情修補，**不需要重新抓取 T86**、也不會遺失既有的三大法人／融資融券資料。

若要肉眼確認某檔股票是否仍有 `0` 值殘留，可執行：

```bash
python -c "import json; d=json.load(open('data/2330.json',encoding='utf-8')); print([k for k,v in d.items() if v['收盤價']==0])"
```
